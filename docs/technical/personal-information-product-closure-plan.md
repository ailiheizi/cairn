## Outcome and existing building blocks

**Operator clarification:** retain the desired outcomes and achieve them by
composing a small shared tool. Reuse is an implementation method, not a reason
to stop at a manual workaround or decline every new capability. Add only the
smallest necessary missing part after its scope/authority review; do not
expand every example into a complete independent domain application.

Keep three distinct records: the user goal and its exit; the shared capability
composition and remaining gap; and the implementation slice admitted at that time.
A goal stays open if the demonstrated recipe is awkward or incomplete. New
semantics trigger review of the necessary gap, not removal of the user goal.

Help one owner keep readable originals, find them from familiar clues, use
supported content and take out or restore exact bytes. One configured
repository and one SQLite catalog remain the physical core; source paths are
provenance and recovery projections.

Use five established building blocks:

1. Exact-preserved readable files.
2. Multiple user tags, including the existing Favorite shortcut.
3. One Notes surface over distinct durable source records.
4. Supported lexical/structured/semantic search and dynamic SavedView queries.
5. Selection, frozen ExportManifest and verified original takeout/recovery.

Current Photos, Music and Overview present this same host authority. The two
compiled client shells shape existing tasks. A recipe does not acquire
another catalog, group engine, query authority or recovery state because it
has a useful name.

TXT, Markdown or JSON may contain URLs, order, dates or location statements.
Preservation does not imply parsing, preview, business validation, calculation,
notifications or automatic updates. Ordinary text search may match those
words without giving them domain semantics. Check actual format support.

## Admission filter

| Disposition | Criterion | Action |
| --- | --- | --- |
| Capability composition | Existing operations meet the agreed user result with acceptable effort; supported/manual steps and unavailable cases are explicit. | Reuse them. Close only the demonstrated result, not every richer variation. |
| Common experience repair | A demonstrated repeated friction/error can be fixed within admitted operations without changing durable or authorization meaning. | Define one small bounded slice with a user-visible exit. Several scenarios sharing a label is insufficient evidence. |
| Necessary capability gap | The agreed result requires missing semantics, interaction, capture, access or lifecycle behavior. | Review the smallest reusable gap and its contracts; after admission schedule a bounded slice. Keep the goal open meanwhile, without assuming a complete domain suite. |

Writing order, location, due or status inside a file is not a schema extension.
Making Cairn interpret them as native business fields is new behavior, even if
called universal. Do not invent universal records, generic Collections or a
task engine to avoid this boundary. A common editor/capture entry is also only
a candidate after a real problem and an admitted scope are established.

## Six compositions and possible gaps

| Example | Existing way to use Cairn | Additional gap to review only if needed |
| --- | --- | --- |
| Reading/research tabs | Owner-written URL/title/order file; tag and Notes for retrieval/progress; read/download it and manually open chosen links. | Tab capture, automatic closing/reopening, historical page or login-state reconstruction. |
| Project research | Related files share a tag; supported tag query/SavedView finds a dynamic set; select/export originals. Put explanation/order in the record. | New project/group state, task hierarchy or group Notes. |
| Passport location | Search an owner-written statement or photo with tags/Notes; update only through a verified existing path or new explicit record. | Native object/location/history semantics or knowledge of actual current location. |
| Manual and invoice | Originals share a tag; warranty text may be in Notes; find/take out originals. | Warranty rules, reminders, attachment semantics or assumed OCR readiness. |
| Food-date list | Maintain dates manually in a file; text search finds the owner's statement. Daily use remains a valid recipe. | Computed expiry windows, inventory consumption or notifications. |
| Mixed trip | Shared tags/search/selection, supported Photos/Music use and exact original export. | Curated albums or persistent playlists; earlier aspirations remain uncommitted here. |

SavedView uses currently supported submitted conditions and dynamic results.
Domain-local filters are not automatically saveable. Only export freezes the
selected versions. A preserved PDF/JSON does not establish a reader. Tagging
files does not create a group Note or authoritative attachment relationship.

## Short-term intent and changed records

Tags and Notes may express read-later/finished intent; human order stays inside
content. No expiry, scheduler or task lifecycle is needed. Tag changes do not
authorize deletion. Use frequency alone does not make a recipe new scope.

Changed bytes have a changed exact identity. Reupload does not imply overwrite,
a stable subject update or an implicit revision. Use a new explicit record or
verified admitted revision path and report how old/new records and tags appear.
A dedicated editor is not assumed present or absent. See the
[short-term recipe](task-context-and-short-lived-information-design.md).

## Goal backlog and qualification boundaries

The desired reading, household, media and customization outcomes remain in
the goal backlog. Their names do not choose an implementation: compose current
capabilities first, then admit necessary gaps individually. Native task state,
capture, calculations, notifications or TV access are possible means, not
automatic feature bundles. Missing implementation scope/sequence does not
cancel the goal. Completion follows its actual user exit, not absence of code
changes or a manually demonstrable subset.

Phase 4/5 may run in parallel only after Phase 3 portable shapes freeze.
Phase 6 LinkGroup stays planned and gated on both; it is a current file-path
map, not an ordered URL session. Phase 7 follows core gates for the declared
profile and need not implement every idea. Recovery authority stays with
repository objects and authenticated records. Runtime third-party code,
kernel ABI and marketplace remain excluded; ADR-032 data-only presentation
composition cannot reach recovery. Product MCP/CLI/AI-harness integration
remains deferred.

Before dispatch, root narrows a ledger item to exact files, one phase, one
normative requirement and one executable exit. Luna handles bounded
implementation/QA; root reviews diff/evidence before changing status.
Report conflicts instead of broadening scope; do not commit. Use proportionate
checks for changed journeys and required cohorts, not repeated passing
matrices. Distinguish real content, fixtures, runtime readiness and release.
