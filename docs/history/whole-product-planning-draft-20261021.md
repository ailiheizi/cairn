## Whole-product delivery roadmap (2026-10-21 inventory)

This section maps the owner’s complete current direction into 67 outcome-level rows grouped into ten themes. The keys are stable references for the roadmap and Linear cards. It is a planning inventory, not a new product authority or a replacement phase order. Product requirements, admitted scope and `docs/technical/core-mvp-execution-plan.md` remain controlling.

### North star and scope boundary

Cairn serves one owner in one self-hosted trust domain. Its core loop protects exact bytes, preserves names/facts/Notes and recovery references, searches lexical, structured and real local semantic information, organizes through the admitted minimal LinkGroup and dynamic SavedView, freezes exports, verifies materialized output and restores exact bytes. Client surfaces share that kernel; source paths remain provenance and recovery projections.

Convergence means finishing admitted core work and first-party experiences. This inventory does not admit a runtime kernel plugin, plugin marketplace, public kernel ABI, multiple tenants, filesystem gateway, OpenList fork, automatic source deletion/download, destructive collection, or neural codec. MCP/CLI/AI-harness integration remains deferred without direct request. Presentation packages are limited to the build/install-time boundary in ADR-032 and cannot reach recovery.

Ordinary material lists remain exact-preserved client files. ML-1/ML-2 support explicit manual or external copy/paste organization, saved playback and existing takeout. Any built-in AI organizer, automatic list head, refresh or execution is a separate future design and admission gate; it is not implied by the current list loop.

### Status and sequencing

Use the inventory stage together with the canonical phase gate. “Locally delivered” means a bounded named journey has evidence, not a complete phase or release. “Implemented and tested” is scoped to the stated development profile. “Candidate”, “planned”, “design”, “blocked”, “future” and “paused” are not completion claims. Keep PASS/FAIL/BLOCKED/NOT RUN honest and name build/environment where evidence exists.

The phase order remains Phase 0 → 1 → 2 → 3 → Phases 4 and 5 in parallel only after Phase 3 portable-record shapes are frozen → Phase 6 after both upstream gates → Phase 7 release qualification. Existing SavedView and flat-export convenience work may continue while gates are open. A group-aware export successor remains gated with LinkGroup; this does not block current single-original, ZIP or flat export UX. Current Photos/Music polish can proceed against admitted journeys without waiting for scale work or complete Phase 4 coverage.

Dependency fields describe implementation prerequisites or reuse, not universal board blocking. Future design and evidence review can proceed without approval to implement. The strict task chain is AIL-7 → AIL-8 → AIL-9 → AIL-10; core LinkGroup/group-aware export and Phase 7 have only their explicit canonical gates. Do not make current Photos/Music polish wait for large-library work or complete Phase 4 coverage.

**WIP 1 / next:** R03 (AIL-7), finish and review the ordinary Skill reuse design. R01/R02 (AIL-5/6) are completed baselines with existing local evidence. R04/R05/R06 (AIL-8/9/10) remain sequential and conditional: R04 follows reviewed actual-gap design; R05 is a separate AI contract and admission gate; R06 cannot start before that approval. R44 is a separate future external AI-client direction and does not depend on a built-in organizer implementation.

### Closed decisions and reopening conditions

These are boundary decisions, not backlog cards. Reopen one only through a direct owner request or a reviewed normative successor tied to a concrete user workflow, with compatibility, safety and recovery analysis where relevant.

- No untrusted runtime kernel plugins, public kernel extension ABI or plugin marketplace. ADR-032 permits only versioned presentation packages admitted whole and composed at build/install time; no package reaches recovery.
- No multi-tenant sharing or enterprise control plane: one instance remains one owner’s trust domain.
- No FUSE/mount, SMB/NFS/WebDAV/S3 gateway, OpenList fork/dependency or media-server gateway in the trusted kernel.
- No automatic external downloading/reacquisition, source deletion, writable source synchronization or destructive garbage collection.
- No RWKV/Transformer/neural codec before simple lossless storage and full recovery are qualified; exact identity remains SHA-256 plus logical length.
- Experimental encryption, cold-media custody, P2P/retrieval and richer remote-source handling remain separate profiles requiring explicit contracts and admission; their mention here grants no implementation scope.
- MCP/CLI/AI-harness integration stays deferred through convergence unless directly requested. R44 describes a future external-client outcome, not current authorization.
